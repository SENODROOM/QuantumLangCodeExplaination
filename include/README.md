# QuantumLanguage Compiler - Parser.h

## Overview

The `include/Parser.h` header file is an integral part of the QuantumLanguage compiler, focusing on the parsing phase of the compilation process. This phase converts source code into an Abstract Syntax Tree (AST), which serves as the intermediate representation used by the compiler for further processing.

## Role in Compilation Pipeline

The parser's primary role is to take a sequence of tokens generated by the lexer and construct a structured AST. This AST represents the syntactic structure of the program, allowing subsequent phases such as semantic analysis, optimization, and code generation to operate on it effectively.

## Key Design Decisions and Why

### Pratt Parsing Algorithm

The parser uses the Pratt parsing algorithm to handle operator precedence and associativity. This approach allows for flexible and efficient parsing of expressions without requiring lookahead beyond the current token. The choice of Pratt parsing was driven by its simplicity and effectiveness in handling complex expression structures.

### Error Handling

The parser includes custom error handling through the `ParseError` class, which extends `std::runtime_error`. This class stores the line and column numbers where the error occurred, providing more context for debugging. The decision to use custom errors instead of standard exceptions was made to ensure better control over error reporting and to avoid unnecessary overhead associated with exception handling.

### Support for Multiple Statement Types

The parser supports various types of statements including variable declarations, function definitions, conditional blocks (`if`, `while`, `for`), loops, and input/output operations. This comprehensive support is essential for building a robust and versatile language.

## Major Classes/Functions Overview

### Parser Class

The `Parser` class is the core component of the parsing module. It takes a vector of `Token`s as input and constructs an AST using a series of parsing functions.

#### Public Methods

- **explicit Parser(std::vector<Token> tokens)**: Constructor that initializes the parser with a list of tokens.
- **ASTNodePtr parse()**: Main method that parses the entire input stream and returns the resulting AST.

#### Private Methods

- **Token &current()**: Retrieves the current token being processed.
- **Token &peek(int offset = 1)**: Looks ahead by a specified number of tokens without advancing the position.
- **Token &consume()**: Advances to the next token and returns it.
- **Token &expect(TokenType t, const std::string &msg)**: Ensures the next token matches the expected type, throwing a `ParseError` otherwise.
- **bool check(TokenType t) const**: Checks if the next token matches the given type without consuming it.
- **bool match(TokenType t)**: Consumes the next token if it matches the given type.
- **bool atEnd() const**: Determines if the end of the token stream has been reached.
- **void skipNewlines()**: Skips any newline tokens encountered during parsing.

### Expression Parsing

The parser includes a set of methods designed to parse different components of expressions according to their precedence levels:

- **parseExpr()**: Parses the highest-level expression.
- **parseAssignment()**: Handles assignment expressions.
- **parseOr(), parseAnd()**: Manage logical operators.
- **parseBitwise()**: Processes bitwise operators.
- **parseEquality(), parseComparison()**: Handle equality and comparison operators.
- **parseShift()**: Parses shift operators.
- **parseAddSub()**: Manages addition and subtraction.
- **parseMulDiv()**: Handles multiplication and division.
- **parsePower()**: Parses power/exponentiation operators.
- **parseUnary()**: Processes unary operators.
- **parsePostfix()**: Handles postfix operators.
- **parsePrimary()**: Parses basic expression elements like literals and variables.

Additional methods support specific expression types:

- **parseArrayLiteral()**: Parses array literals.
- **parseDictLiteral()**: Parses dictionary literals.
- **parseLambda()**: Constructs lambda expressions.
- **parseArrowFunction(std::vector<std::string> params, int ln)**: Creates arrow function syntax.
- **parseArgList()**: Parses argument lists for functions or lambdas.
- **parseParamList(std::vector<bool> *outIsRef = nullptr, std::vector<ASTNodePtr> *outDefaultArgs = nullptr, std::vector<std::string> *outParamTypes = nullptr)**: Parses parameter lists, identifying reference parameters and default arguments.

## Tradeoffs

### Flexibility vs. Complexity

Using the Pratt parsing algorithm provides significant flexibility in handling different operator precedences and associativities. However, this comes with increased complexity in the implementation, particularly in managing operator binding and precedence rules.

### Error Reporting

Custom error handling enhances the clarity and precision of error messages, making debugging easier. While this improves user experience, it also adds additional overhead compared to using standard exceptions.

### Comprehensive Coverage

Supporting multiple statement types and expression components requires careful planning and implementation. This comprehensive coverage ensures that the language can handle a wide range of programming tasks but may increase the initial development time and maintenance burden.

In conclusion, the `Parser.h` header file is a critical component of the QuantumLanguage compiler, leveraging advanced parsing techniques to convert source code into a structured AST. Its role in the compilation pipeline is pivotal, and the design decisions made reflect a balance between flexibility, error reporting, and comprehensive coverage.
