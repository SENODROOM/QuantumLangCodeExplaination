# QuantumLanguage Compiler - Opcode.h

## Overview

The `include/Opcode.h` header file defines the set of operations (opcodes) used by the QuantumLanguage compiler's virtual machine (VM). These opcodes dictate how the VM processes bytecode during execution, ensuring efficient and accurate program execution.

## Role in Compiler Pipeline

### Compilation Phase
- **Bytecode Generation**: During the compilation phase, the QuantumLanguage compiler translates high-level source code into a low-level bytecode format. This bytecode consists of sequences of opcodes along with their operands.
  
### Execution Phase
- **Virtual Machine Execution**: The generated bytecode is then executed by the VM, which interprets each opcode according to its definition in `Opcode.h`.
  
## Key Design Decisions and Why

1. **Stack-Based Architecture**:
   - **Why**: A stack-based architecture simplifies memory management and allows for efficient execution of operations like arithmetic and comparisons.
   
2. **Dynamic Typing**:
   - **Why**: QuantumLanguage supports dynamic typing, making it necessary to handle different types of data (e.g., integers, strings, objects) within the same stack frame.
   
3. **Exception Handling**:
   - **Why**: Proper exception handling is essential for robust program execution. QuantumLanguage includes opcodes for pushing, popping, raising, and re-raising exceptions, allowing for structured error handling.
   
4. **Pointer Support**:
   - **Why**: QuantumLanguage extends C++, incorporating pointer support to allow for more complex data structures and object-oriented programming features.
   
5. **Efficient Memory Management**:
   - **Why**: QuantumLanguage uses techniques like garbage collection and upvalue promotion to manage memory effectively, preventing memory leaks and optimizing performance.
   
## Major Classes/Functions Overview

### `Op` Enum Class
- **Purpose**: Defines an enumeration of all possible opcodes used by the VM.
- **Key Operations**:
  - **Stack Manipulation**: Operations like `LOAD_CONST`, `POP`, `LOAD_GLOBAL`, etc.
  - **Arithmetic**: Operations like `ADD`, `SUB`, `MUL`, etc.
  - **Comparison**: Operations like `EQ`, `NEQ`, `LT`, etc.
  - **Logical**: Operations like `NOT`, `AND`, `OR`, etc.
  - **String Operations**: Operation like `CONCAT`.
  - **Control Flow**: Operations like `JUMP`, `LOOP`, `JUMP_ABSOLUTE`, etc.
  - **Function Calls**: Operations like `CALL`, `RETURN`, `MAKE_FUNCTION`, etc.
  - **Collections**: Operations like `MAKE_ARRAY`, `MAKE_DICT`, `MAKE_TUPLE`, etc.
  - **Member Access**: Operations like `GET_INDEX`, `SET_INDEX`, `GET_MEMBER`, etc.
  - **Iteration**: Operations like `FOR_ITER`, `MAKE_ITER`, etc.
  - **Classes and Objects**: Operations like `MAKE_CLASS`, `INHERIT`, `BIND_METHOD`, etc.
  - **Exceptions**: Operations like `PUSH_HANDLER`, `POP_HANDLER`, `RAISE`, `RERAISE`, etc.
  - **Pointers**: Operations like `ADDRESS_OF`, `DEREF`, `ARROW`, etc.
  - **Miscellaneous**: Operations like `PRINT`.

### `Value` Class
- **Purpose**: Represents the data type used by the VM, capable of holding various types including numbers, strings, booleans, and pointers.
- **Key Features**:
  - **Type Information**: Tracks the type of the value.
  - **Data Storage**: Stores the actual data in a union.
  - **Memory Management**: Handles memory allocation and deallocation for dynamically typed values.

## Tradeoffs

1. **Performance vs. Simplicity**:
   - **Tradeoff**: Using a stack-based architecture provides simplicity but may sacrifice some performance compared to register-based architectures.
   
2. **Garbage Collection Overhead**:
   - **Tradeoff**: Implementing garbage collection adds overhead to the execution process but helps prevent memory leaks and optimize memory usage.
   
3. **Dynamic Typing Flexibility vs. Type Safety**:
   - **Tradeoff**: Dynamic typing offers flexibility but can lead to runtime errors if not handled properly. Static typing would provide better type safety but increase complexity in the compiler pipeline.

By carefully designing these opcodes and supporting classes, the QuantumLanguage compiler aims to balance efficiency, flexibility, and robustness, enabling developers to write powerful and performant quantum language applications.
