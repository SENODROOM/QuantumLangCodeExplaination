# QuantumLanguage Compiler - Compiler.h

## Overview

The `include/Compiler.h` header file is integral to the QuantumLanguage compiler, focusing on the core functionality of compiling source code into executable chunks. This file defines essential components such as the Virtual Machine (VM), compiler states, and various helper functions to manage the compilation process effectively.

## Role in Compilation Pipeline

The `Compiler.h` file serves as a central component in the QuantumLanguage compiler's pipeline. It handles the translation of abstract syntax trees (ASTs) generated by the parser into bytecode instructions that can be executed by the VM. The primary responsibilities include:

- **Code Generation**: Converting AST nodes into corresponding bytecode operations.
- **Scope Management**: Tracking variable declarations and their visibility across different scopes.
- **Error Handling**: Managing exceptions and reporting errors during the compilation phase.
- **Optimization**: Implementing optimizations to improve the performance of the generated bytecode.

## Key Design Decisions and Why

### Modular Architecture

The compiler is designed with a modular architecture, where each part of the compilation process is encapsulated within specific classes and functions. This approach enhances maintainability and scalability by allowing developers to focus on individual aspects of the compiler without being overwhelmed by the entire system.

### Use of Shared Pointers

To manage memory efficiently and avoid dangling pointers, shared pointers (`std::shared_ptr`) are extensively used throughout the compiler. This choice simplifies resource management and reduces the risk of memory leaks, ensuring that all dynamically allocated resources are properly cleaned up when they are no longer needed.

### Opcode-Based Bytecode

The compiler uses an opcode-based bytecode representation, which allows for efficient execution by the VM. Each opcode corresponds to a specific operation, making it easy to decode and execute instructions. This design also facilitates future extensions and modifications to the compiler without breaking existing code.

## Major Classes/Functions Overview

### Compiler Class

The `Compiler` class is the main entry point for the compilation process. It manages the overall state of the compiler, including the current chunk of bytecode being generated and the stack of compiler states representing nested scopes. The key methods include:

- `compile(ASTNode &root)`: Compiles the entire program starting from the root AST node.
- `compileNode(ASTNode &node)`, `compileBlock(BlockStmt &b)`, `compileExpr(ASTNode &node)`: Recursive methods to handle different types of AST nodes.
- `compileVarDecl(VarDecl &s, int line)`, `compileFunctionDecl(FunctionDecl &s, int line)`, `compileClassDecl(ClassDecl &s, int line)`, `compileIf(IfStmt &s, int line)`: Methods to compile specific types of statements like variable declarations, function definitions, class definitions, and conditional statements.

### CompilerState Struct

The `CompilerState` struct represents the state of the compiler at any given point. It contains information about the current chunk of bytecode, local variables, upvalues, scope depth, and the enclosing compiler state. This structure is crucial for managing nested scopes and capturing variables from outer scopes.

### Helper Functions

Several helper functions are provided to simplify the compilation process:

- `emit(Op op, int32_t operand = 0, int line = 0)`: Emits a bytecode instruction into the current chunk.
- `addConst(QuantumValue v)`, `addStr(const std::string &s)`: Adds constants and strings to the chunk's constant pool.
- `emitJump(Op op, int line = 0)`, `patchJump(size_t idx)`: Handles jump instructions and patches them after the target address is determined.
- `beginScope()`, `endScope(int line = 0)`: Manages the start and end of new scopes.
- `resolveLocal(CompilerState *state, const std::string &name)`, `resolveUpvalue(CompilerState *state, const std::string &name)`, `addUpvalue(CompilerState *state, int index, bool isLocal)`, `declareLocal(const std::string &name, int line = 0)`: Functions to resolve and manage local and upvalue variables.

## Tradeoffs

While the modular architecture and use of shared pointers provide significant benefits in terms of maintainability and memory management, there are some tradeoffs to consider:

- **Complexity**: The modular design increases complexity, requiring more time and effort to understand and debug the compiler.
- **Memory Overhead**: Using shared pointers introduces additional memory overhead due to reference counting.
- **Performance**: In some cases, the overhead associated with dynamic memory allocation and reference counting may impact performance.

Despite these tradeoffs, the benefits of a modular and scalable design outweigh the potential drawbacks, making this approach ideal for large-scale compilers like QuantumLanguage.
