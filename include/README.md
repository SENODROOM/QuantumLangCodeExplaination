# QuantumLanguage Compiler - Compiler.h

## Overview

The `include/Compiler.h` header file is integral to the QuantumLanguage compiler, focusing on the definition of the Compiler class. This class is pivotal in transforming abstract syntax trees (ASTs) into executable bytecode chunks. The Compiler manages various aspects such as scope resolution, variable declarations, function definitions, and class declarations, ensuring efficient and accurate execution of the compiled code.

## Role in Compiler Pipeline

The Compiler operates within the broader context of the QuantumLanguage compiler pipeline. Its primary responsibilities include:

- **Parsing**: Converting source code into an AST.
- **Compilation**: Translating the AST into bytecode chunks.
- **Bytecode Execution**: Passing the generated bytecode to the Virtual Machine (VM) for execution.

The Compiler class acts as a bridge between the parsing phase and the VM, handling the intricate details required for translation and ensuring that the resulting bytecode is optimized for performance and correctness.

## Key Design Decisions and Why

### 1. Use of Shared Pointers for Chunks

**Why**: Utilizing shared pointers (`std::shared_ptr`) for the `Chunk` objects allows for automatic memory management, preventing memory leaks and simplifying resource sharing across different parts of the compiler.

### 2. Hierarchical Scope Management

**Why**: Implementing a hierarchical scope system using nested `CompilerState` structures enables the Compiler to manage local variables, captured variables, and upvalues effectively. This approach ensures that variable lookups are performed correctly and that upvalues are properly handled during compilation.

### 3. Opcode Emitters with Line Numbers

**Why**: Each opcode emission includes a line number, which facilitates debugging and error reporting. This feature aids developers in tracing issues back to their source code locations.

## Major Classes/Functions Overview

### Compiler Class

#### Public Methods

- `compile(ASTNode &root)`: Compiles an entire program represented by the root AST node and returns the top-level `Chunk`.

#### Private Members

- `current_`: Points to the active `CompilerState`, representing the current scope being compiled.
- `chunk()`: Returns a reference to the current chunk being compiled.
- `emit(Op op, int32_t operand = 0, int line = 0)`: Emits an opcode into the current chunk, optionally including an operand and line number.
- `addConst(QuantumValue v)`: Adds a constant value to the current chunk and returns its index.
- `addStr(const std::string &s)`: Adds a string literal to the current chunk and returns its index.
- `emitJump(Op op, int line = 0)`: Emits a jump opcode and returns its index for later patching.
- `patchJump(size_t idx)`: Patches a previously emitted jump opcode with the correct offset.

### CompilerState Struct

Represents the state of a compiler during a particular scope. Contains information about the current chunk, local variables, upvalues, and the enclosing scope.

### Local Struct

Stores details about a local variable, including its name, depth within the scope, and whether it has been captured as an upvalue.

### UpvalueDesc Struct

Describes an upvalue, indicating whether it is captured from a local variable or an outer upvalue, along with its slot index.

### Helper Functions

- `beginScope()`: Begins a new scope.
- `endScope(int line = 0)`: Ends the current scope, optionally emitting a debug line number.
- `resolveLocal(CompilerState *state, const std::string &name)`: Resolves the index of a local variable within the given scope.
- `resolveUpvalue(CompilerState *state, const std::string &name)`: Resolves the index of an upvalue within the given scope.
- `addUpvalue(CompilerState *state, int index, bool isLocal)`: Adds an upvalue to the current scope.
- `declareLocal(const std::string &name, int line = 0)`: Declares a new local variable within the current scope.

## Tradeoffs

### Memory Management

Using shared pointers for `Chunk` objects simplifies memory management but may introduce overhead compared to raw pointers.

### Scope Resolution Complexity

Hierarchical scope management provides robustness but can increase complexity in terms of code and performance.

### Debugging Information

Including line numbers in each opcode emission enhances debugging capabilities but adds additional data to the bytecode.

Overall, the Compiler class and related components offer a comprehensive solution for compiling QuantumLanguage programs into executable bytecode, balancing functionality, efficiency, and ease of use.
