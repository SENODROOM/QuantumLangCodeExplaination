# LexerCore Component of the Quantum Language Compiler

## Overview

The `lexercore` component is a fundamental module within the Quantum Language (QL) compiler designed to convert source code into a sequence of tokens. This conversion is critical for the subsequent phases of parsing and compilation. The main objective of `lexercore` is to precisely identify and classify lexical elements from the input source code, ensuring accurate translation into an abstract syntax tree (AST).

## Components

### current()
- **Description**: Returns the current token being processed.
- **Usage**: Used to access the most recently identified token during the lexing phase.

### peek()
- **Description**: Returns the next token without advancing the lexer's position.
- **Usage**: Useful for lookahead operations where the next token needs to be examined without consuming it.

### advance()
- **Description**: Advances the lexer to the next token.
- **Usage**: Called iteratively to move through the source code, identifying each token in turn.

### skipWhitespace()
- **Description**: Skips over any whitespace characters encountered in the source code.
- **Usage**: Ensures that only meaningful tokens are considered during the lexing process.

### skipComment()
- **Description**: Skips over single-line comments in the source code.
- **Usage**: Removes comment text from the input stream, preventing it from being treated as part of the program.

### skipBlockComment()
- **Description**: Skips over multi-line block comments in the source code.
- **Usage**: Handles comments that span multiple lines, ensuring they do not interfere with tokenization.

### readNumber()
- **Description**: Reads a numeric literal from the source code and returns it as a token.
- **Usage**: Converts sequences of digits into numerical tokens, handling both integer and floating-point values.

## Flow

1. **Initialization**: The lexer starts by reading the first character of the source code.
2. **Token Identification**: It then identifies the type of the token based on the character(s) read.
3. **Skip Whitespace/Comments**: If the token is whitespace or a comment, the lexer skips over it and continues to the next character.
4. **Read Number**: For numeric literals, the lexer calls `readNumber()` to parse and return the corresponding token.
5. **Advance**: Once a token is identified and processed, the lexer advances to the next character using `advance()`.
6. **Repeat**: Steps 2-5 are repeated until the end of the source code is reached.
7. **Output**: Finally, the sequence of tokens generated by the lexer is outputted for further processing by the parser.

## Files

- `current.cpp`: Contains the implementation of the `current()` function.
- `peek.cpp`: Implements the `peek()` function for lookahead capabilities.
- `advance.cpp`: Provides the logic for advancing the lexer's position.
- `skipWhitespace.cpp`: Manages the skipping of whitespace characters.
- `skipComment.cpp`: Handles the removal of single-line comments.
- `skipBlockComment.cpp`: Processes multi-line block comments.
- `readNumber.cpp`: Parses numeric literals and returns them as tokens.

Each file corresponds to a specific functionality within the lexer core, contributing to the overall accuracy and efficiency of the tokenization process.
