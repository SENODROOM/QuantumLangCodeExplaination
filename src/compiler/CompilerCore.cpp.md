# Quantum Language Compiler Core

## Overview

`src/compiler/CompilerCore.cpp` is a critical component of the Quantum Language compiler, responsible for converting Abstract Syntax Trees (ASTs) into executable bytecode. This file encapsulates the core logic necessary to manage various AST nodes and ensure the smooth execution of the compilation process.

### Role in Compiler Pipeline

The `CompilerCore.cpp` plays a pivotal role within the compiler's pipeline:
1. **Parsing**: The AST is generated by the parser.
2. **Compilation**: The `compile()` function processes the AST and generates bytecode.
3. **Optimization**: Optimizations can be applied before finalization.
4. **Output**: The resulting bytecode is outputted for execution.

This modular approach allows for efficient handling of different types of AST nodes and ensures that each stage of the compilation process is well-defined and manageable.

### Key Design Decisions and Why

#### Local Variable Resolution

- **Why**: Efficiently managing local variables is crucial for performance and correctness.
- **How**: The `resolveLocal()` function searches for a variable in the current scope and returns its index if found. If not found, it returns `-1`.

#### Upvalue Management

- **Why**: Handling upvalues (variables captured by closures) requires careful tracking and management.
- **How**: The `addUpvalue()` function adds an upvalue to the current chunk, ensuring that the correct number of upvalues are tracked. The `resolveUpvalue()` function resolves upvalues by searching both the current and enclosing scopes.

#### Scope Management

- **Why**: Proper scope management prevents variable shadowing and ensures that variables are accessible where they should be.
- **How**: The `beginScope()` and `endScope()` functions manage the depth of the current scope. When a new scope begins, `beginScope()` increments the depth. When a scope ends, `endScope()` decrements the depth and pops locals until the depth matches the current scope.

#### Error Handling

- **Why**: Robust error handling is essential for debugging and maintaining code quality.
- **How**: The compiler uses exceptions (`std::runtime_error`) to handle errors during compilation. Errors are reported using the `reportError()` function, which provides detailed information about the error location and nature.

### Major Classes/Functions Overview

#### Compiler Class

- **Purpose**: Manages the overall compilation process.
- **Key Functions**:
  - `compile(ASTNode &root)`: Compiles the root node of the AST.
  - `emit(Op op, int arg1, int arg2)`: Emits a bytecode instruction.
  - `emitLoad(const std::string &name, int line)`: Emits a load instruction for a local or global variable.
  - `emitStore(const std::string &name, int line)`: Emits a store instruction for a local or global variable.

#### CompilerState Struct

- **Purpose**: Holds the state of the compiler at any given point.
- **Fields**:
  - `chunk`: Pointer to the current chunk of bytecode being generated.
  - `scopeDepth`: Current depth of the scope.
  - `locals`: List of local variables in the current scope.
  - `upvalues`: List of upvalues captured by closures.
  - `enclosing`: Pointer to the enclosing scope.

#### Local Struct

- **Purpose**: Represents a local variable.
- **Fields**:
  - `name`: Name of the local variable.
  - `depth`: Depth at which the local variable is declared.
  - `isCaptured`: Flag indicating whether the local variable is captured by a closure.

#### Upvalue Struct

- **Purpose**: Represents an upvalue (a local variable captured by a closure).
- **Fields**:
  - `isLocal`: Flag indicating whether the upvalue refers to a local variable in the enclosing scope.
  - `index`: Index of the upvalue in either the local or upvalue lists of the enclosing scope.

### Tradeoffs

- **Performance vs. Memory**: Managing scopes and upvalues requires additional memory to track local and upvalue indices. However, this tradeoff ensures efficient access and modification of variables, enhancing overall performance.
- **Complexity vs. Simplicity**: The introduction of upvalues and closures adds complexity to the compiler. While this increases the functionality and flexibility of the language, it also makes the implementation more intricate.
- **Error Handling vs. Usability**: Comprehensive error handling improves the reliability of the compiler but may introduce overhead. Balancing robustness with usability is essential for practical applications.

By understanding these aspects, developers can better appreciate the design choices behind the Quantum Language compiler and how they contribute to its performance and functionality.
